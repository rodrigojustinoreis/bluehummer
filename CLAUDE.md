# Blue Hammer Remodeling

Website and online presence for Blue Hammer Remodeling: small repairs up to full kitchen, bath and
basement remodels. Based in Olney, MD 20832; serves Maryland, Washington, DC and Virginia within about
40 miles (owner decision 2026-11-18; DC/VA licensing unconfirmed, never claim it). See HARD-RULES.md.

For any task about content, SEO, images, design, or online presence, and for every
headless or autonomous run, start the **`bh-orchestrator`** agent
(`.claude/agents/bh-orchestrator.md`). It reads the audit and `AGENT-LOG.md`,
picks the next stage, delegates to specialist subagents (`bh-designer`,
`bh-seo-content`, `bh-images`, `bh-qa`), runs the quality gate, and only then
commits and pushes to `main` (Netlify deploys). Headless entry point:
`scripts/run-orchestrator.sh`. The `bluehammer` agent is a compatibility alias
that follows the orchestrator. Never invent reviews, credentials, or contact details.
All agents follow `.claude/agents/HARD-RULES.md`.

## Design and images (owner rules, 2026-11-18)
- Every design, image or copy task reads `docs/brand.md` and `docs/design-system/README.md`
  first and uses the `anthropic-frontend-design` skill plus the project skills in
  `.claude/skills/` (`bh-design-loop`, `bh-design-check`, `bh-anti-slop-copy`,
  `bh-section-references`). Goal: premium, editorial, high-end Maryland remodeler; no
  generic AI-template look.
- Images may be AI-generated and are never labeled as AI (no tags, badges, captions, alt
  text, filenames or disclaimers saying AI/concept/inspiration). They must never be
  presented as completed Blue Hammer projects, real clients, employees or before/after work.
- No invented facts, numbers, licenses, reviews or contact details in copy. Free tools only.

## Method, tools and verified commands (setup 2026-11-18)
- **Method:** the project skill `blue-hammer-website` (`.claude/skills/blue-hammer-website/`) is the
  10-step page method and remodeling criteria used by all bh-* agents. Facts: `.agents/product-marketing.md`
  and its `references/evidence.md`. Visual identity: `DESIGN.md` (summary + known gaps) -> `docs/brand.md` (spec).
- **Tech:** static HTML generated by Python (`scripts/build.py`) into `blue_hammer_remodeling_site/`
  (Netlify publish dir, Netlify Forms). No JS framework, so no React/Next skills. Node is dev tooling only
  (`tools/package.json`, never part of the site build).
- **Verified commands:**
  - Build + checks: `python3 scripts/build.py --check`
  - Local preview: `cd blue_hammer_remodeling_site && python3 -m http.server 8765 --bind 127.0.0.1`
  - Browser: `tools/node_modules/.bin/playwright-cli -s=bh open http://127.0.0.1:8765/` then `screenshot`,
    `resize 390 844`, `console`, `close` (skill: `playwright-cli`). Uses the installed Chrome.
  - Reinstall dev tools: `npm --prefix tools install`. Skill sources and commits are pinned in `skills-lock.json` (vercel-labs/skills CLI).
- **Skills (project `.claude/skills/`):**
  - Design: `anthropic-frontend-design` (direction/build), `impeccable` (critique, audit, polish, typeset,
    layout, harden only; hooks and live mode are NOT enabled; its engine binary downloads on first
    `scripts/impeccable` run), `bh-design-loop`, `bh-design-check`, `bh-section-references`.
    Personal skills still used: `better-interface` family, `slopmonster`, `web-interface-guidelines`.
  - Review: `web-interface-guidelines` (local copy, **preferred**, no network). `web-design-guidelines`
    (Vercel) fetches its rules from GitHub on every run; use only when the network fetch is acceptable.
  - Marketing/SEO: `product-marketing`, `site-architecture`, `copywriting`, `cro`, `schema`,
    `marketing-seo-audit` (= marketingskills `seo-audit`, renamed so it does not clash with the personal
    `seo-audit`). Copy also goes through `bh-anti-slop-copy`.
  - Testing: `playwright-cli` (primary browser flow), `webapp-testing` (Python Playwright scripts for local pages).
- **MCP (project `.mcp.json`):** `context7` (library docs: `resolve-library-id` -> `query-docs`; use it before
  relying on any library/API detail, for the version in use) and `chrome-devtools` (isolated headless Chrome:
  console, network, Lighthouse, performance traces). Do not add Playwright MCP; the CLI covers it.
- **Review / done:** build check passes, `bh-design-check` passes, `bh-qa` PASS, screenshots at 390 and
  1440 px looked at, no unconfirmed facts, log updated.
- **Local vs publish:** editing files changes only this checkout. Publishing = commit + push to `main`
  (Netlify auto-deploys); only `bh-orchestrator` does that, after the gate. Never submit the real
